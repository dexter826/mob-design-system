Keyboard focus

The focus treatment is not a shadow step. Every interactive element draws the same ring: 0 0 0 2px #0a0a0a, then 0 0 0 4px #00cc5c. Tab through the two buttons to see it.

  • ProhibitedColored shadows are not part of the system. No neon-green drop shadow, no glow or bloom on edges, no blurred gradient blob behind content. The only non-black shadow value in the source is the accent inside the focus ring, and that is a ring, not elevation. The rule is a use rule: #00cc5c at 100% chroma is saturation, not light, so the accent never carries text below 14px, is never a large background wash, and a glow is never used to imply the brightness.
  • Two spellingsdesign-tokens.json gives md and lg one layer each. design-system.css pairs them with a second black layer, 0 2px 4px -2px and 0 4px 6px -4px at the same alpha. Both are black-only, so the difference is depth, not color.
  • Contrast does the workMost state changes skip shadows: hover steps the surface up one level and the border from #262626 to #383838, and the interactive card changes border-color only. Elevation is reserved for layers that genuinely float.
  • Focus everywhereButtons, inputs, links, table rows that take actions and any element reachable by Tab all show the identical ring, with no layout shift and no change to the element's own border except on inputs, which set border-color #00cc5c. The ring clears the 3:1 non-text floor everywhere it lands: 9.23:1 on the canvas, 8.73:1 on surface, 8.28:1 on the surface-subtle stage above.
