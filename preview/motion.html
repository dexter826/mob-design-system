Motion

One measured duration, one curve, three properties. The source bans entrance choreography, so this system has no draw-on, no slide, no scale, no stagger and no spinner. The only additions are two opacity fades for overlays and one width change for a determinate progress bar — both recorded as amendments below.

Stagger is stated as 0s rather than left blank because the general motion baseline most product teams default to includes a per-item delay, and this system explicitly does not. The reason is the source line itself: entrance choreography is banned, so there is no entrance to delay. Five cards arriving 40ms apart is still five entrances. A list renders in one frame, in DOM order, and reads top-down; if a reviewer asks for a stagger, the answer is the amendment log, not a new token. Both curves are single-purpose: the decelerate curve lands, the accelerate curve leaves, and nothing in this system bounces, overshoots or loops.

Hover and press

transition-duration readingproperties background-color, border-color, color

Hover and press move fill, border and text colour only. The buttons do not lift, grow, shadow, slide or change size, and hover never makes text lighter than #ededed — the ghost rule in the component contract. The disabled state is opacity 0.4 with the label held in place, not a fade-out. Focus uses the one ring recipe for the whole system: 2px of canvas then 4px of accent, drawn with no layout shift.

Overlay fade

Behind the panel: the surface stays --color-surface. This card fades the panel alone and dims nothing — the contract registers no scrim colour, and overlays.css carries its wash as black at a capped element opacity rather than a new literal.

The two durations are printed above from the live computed values of the tokens, so the card cannot disagree with the contract — under prefers-reduced-motion they both re-read as 0.01ms. pointer-events flips with the state and this demo binds Escape. A real overlay must additionally leave the tab order when closed and trap focus while open: opacity is a paint channel, not an accessibility state, and a fade alone does not hide a panel from a keyboard. overlays.css pairs the same two durations with visibility for exactly that reason; the specimen here is the minimal form, and overlays.css is the shipped recipe.

This is the only element in the system that animates a geometry property, and it animates width rather than transform: scaleX() — a scale is banned outright, and a scaleX would also stretch the fill's 1px border into a different weight. The bar is a value that changes, not an element that arrives, so the amendment is narrower than it looks. The fill runs in --color-info while work is in flight and takes the accent only at 100%, because green marks the healthy state and never the act of progressing. The commit hash is 7 characters in mono. A step is enough for a reviewer to see the 0.24s; nothing here polls a server.

Skeleton, and what is banned

Loading placeholder

Flat --mob-signal-skeleton-fill, one step above the card, 1px border, no shimmer, no pulse, no gradient sweep. A shimmer is an infinite loop with no information in it; the static block says "content pending" just as clearly and costs nothing. The line widths are percentages of the placeholder's own measure, not new spacing steps.

Banned

  • No slide. Nothing moves on either axis as it appears.
  • No scale. No size change, no zoom-in, no press-to-shrink.
  • No shimmer. No gradient animation over a placeholder.
  • No spinner. No indeterminate rotation exists in this system.
  • No stagger. No per-item entrance delay; the value is 0s.
  • No parallax, glow or trail. Depth is a surface step plus a border.

Used

  • Color at 0.12s — hover, press, selection, focus.
  • Opacity at 0.12s in, 0.08s out — overlays only.
  • Width at 0.24s — a determinate progress bar only.
  • Nothing at 0.01ms — reduced motion, same layout.

There is no indeterminate spinner in this system, so a waiting state is a determinate bar with a percentage, or a static skeleton, or a word — "Queued", "Pending" — in the status column. The archive defines no spinner recipe, and an indeterminate loop is motion that carries no measurement, which is exactly what the source excludes.

Reduced motion

The contract collapses every duration to 0.01ms and changes no layout property. A transition to 0.01ms is an instant state change, not a hidden animation: the panel is still open after the click, the bar still shows the new value, the skeleton is still a block, and nothing moves to a different place because nothing was ever moving.

@media (prefers-reduced-motion: reduce) { :root { --mob-signal-motion: 0.01ms; --mob-signal-motion-hover: 0.01ms; --mob-signal-motion-enter: 0.01ms; --mob-signal-motion-exit: 0.01ms; --mob-signal-motion-progress: 0.01ms; } *, *::before, *::after { animation-duration: 0.01ms !important; animation-iteration-count: 1 !important; transition-duration: 0.01ms !important; scroll-behavior: auto !important; } }

This card repeats the guard locally for the elements it demos — .btn, .panel, .fill and the table rows — so the collapse is visible in the file a reviewer opens, not only in the shared sheet. Restating it is safe because the local block only narrows durations; a component that lengthened one, or set transition: all, would be a defect against the contract. With the preference on, the readouts above both show 0.01ms, which is the fastest way to confirm this card is reading the tokens rather than the text next to them.

Provenance. Measured: the single value 0.12s cubic-bezier(0.16, 1, 0.3, 1) on background-color, border-color and color, taken from design-tokens.json and design-system.css. The brand rule is "Motion is a single 0.12s ease-out on background-color, border-color and color only. No scale, no parallax, no entrance choreography." Three values extend it, and each is recorded as authored rather than measured. (1) --motion-enter 0.12s and --motion-exit 0.08s hold the "color only" clause literally: opacity is a colour channel, not a geometric one, so an element that fades never changes position or size and never enters with choreography — the fade reuses the measured duration and adds no new timing except the 67% exit. (2) --motion-progress 0.24s touches the "no scale" clause only in the sense that it animates a size: it is permitted for a determinate progress bar, whose width is a reported value, and it is expressed as width rather than transform: scaleX() so no scale function appears anywhere in the system. (3) The prefers-reduced-motion block collapses the three authored values and the measured value alike; the archive carries no entrance to remove, so it addresses nothing here. Stagger stays 0s, the skeleton stays flat, and no indeterminate spinner is claimed. Exit easing cubic-bezier(0.7, 0, 0.84, 0) is the only curve here that has no counterpart in the archive.
